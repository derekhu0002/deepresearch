# 麦肯锡结构化战略分析新5步法

本技能将意图图谱元素「麦肯锡结构化战略分析新5步法」固化为可执行方法，用于展开业务洞察类 Work Package。元素链：驱动因素 → 问题 → 结构化分析 → 决策树 → 提出假设 → 假设 → 收集数据 → 数据 → 验证假设 → 解答问题。

## 五步流程

### 1. 基于外部驱动因素定义问题
- 首先挑战问题定义：确保要解决的问题是清晰、具体且可衡量的（SMART 原则）。
- 从外部驱动因素出发定义问题，明确问题的 Goal、Outcome 与 Course of Action 落点。

### 2. 结构化分析
- 将问题拆解为决策树，必须至少形成三层。
- 每一层拆解必须严格遵守 MECE 原则（相互独立，完全穷尽）。
- 必须明确说明拆解的维度与方法，并论证该拆解既覆盖所有可能性、又没有重叠。
- 决策树遍历：针对每个分支进行无情追问，理顺所有依赖关系。

### 3. 提出假设
- 从决策树分支生成可证伪的业务假设；分支节点不是假设，对每个分支提出的问题构成待验证假设。
- 每个假设必须先显式声明「假设陈述 + 可证伪条件」（出现何种事实即宣告该假设不成立）。

### 4. 收集数据
- 按证据权威优先级与 Automatic Work Delegation Governance 动态确定 Agent 数量与并发度，并发取证，优先寻址反例。
- 在五个证据平面取证：意图架构图谱 / 代码中的实现架构设计 / 代码与测试本身 / 互联网来源 / 人类用户验收人。

### 5. 验证假设
- 每个假设的结论必须且只能取三态之一：supported（被支持）/ refuted（被证伪）/ undetermined（证据不足）。
- 反例优先与红蓝对抗：主动搜寻可证伪该假设的反例证据，而非只收集支持性证据；每个 core hypothesis 都要有独立于支持性论证的检验角色。

## 输出要求
- 以决策树为载体，将每个假设及其验证状态标注为所属分支节点的附着信息。
- 每个结论都必须给出论据来源（URL 链接 + 原文段落）。
- 给出验收测试标准：每个测试用例必须包含从验收方视角的控制点和观测点，保持业务语义，不定义实现级测试细节。
